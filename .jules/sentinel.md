## 2025-02-14 - Fix XSS Vulnerability Bypass using `&equals;`
**Vulnerability:** A Cross-Site Scripting (XSS) vulnerability existed where attackers could bypass the inline event handler sanitization in `sanitizeString` by obfuscating the `=` sign using the `&equals;` HTML entity or its numeric equivalents (e.g. `&#61;`, `&#x3d;`). For instance, `<img src=x onerror&equals;alert(1)>` was parsed safely by browsers but missed by the sanitization regex. Furthermore, dangerous URIs using `&equals;` could bypass the blocklist because the URL entity decoder didn't decode `&equals;`.
**Learning:** Browsers decode HTML entities in attributes and element content before executing scripts or applying styles. When sanitization steps occur iteratively—such as stripping event handlers before fully decoding all entities—regex patterns must account for encoded characters (like `=`) that may serve as structural boundaries.
**Prevention:** Always ensure standard structural HTML entities (like `=`, `"`, `'`, `<` and `>`) are decoded appropriately in the custom `decodeHtmlEntities` function. Additionally, when using regex to neutralize inline event handlers prior to full entity decoding, ensure the pattern explicitly matches obfuscated forms of the equals sign `(?:=|&equals;?|&#x3d;?|&#61;?)`.
