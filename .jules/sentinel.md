## YYYY-MM-DD - [Prevent DoS in XSS Filter via Local URI Replacement]
**Vulnerability:** The `sanitizeString` XSS filter mitigated dangerous URI schemes by returning `#blocked-uri` for the entire string if a match was found in the decoded version. An attacker could intentionally input a harmless-looking prefix like `="javascript:` alongside valid text, which would trigger the filter and cause a Denial of Service by completely deleting the valid data field.
**Learning:** XSS mitigations must operate precisely on the malicious payload without blindly rejecting the entire string, especially in fields intended for general user input. However, attempting to perform local string replacements by parsing HTML manually via Regular Expressions introduces massive bypass vectors (like `<a/href` and unclosed tags).
**Prevention:** To safely perform local replacements of dangerous URIs without an HTML parser, dynamically construct a highly specific RegExp that explicitly accounts for all obfuscation combinations (HTML entities, hex codes, interspersed whitespace, and control characters) generated programmatically. This ensures the targeted string replacement neutralizes the exact malicious URI locally, preserving surrounding text without opening up HTML parsing bypasses. When building complex RegExp string literals programmatically in Node.js, rigorously ensure backslashes for special character classes like `\s` are double-escaped to avoid "Nothing to repeat" compilation errors.
