## 2024-05-18 - [Optimization] Grid generation for A* orthogonal edge routing
**Learning:** In `@pgv/graph-core`, the A* grid generation within `routeEdgeOrthogonal` (`src/layout.ts`) was only registering the horizontal center line of nodes (`xSet.add(pos.x + size.width / 2)`), omitting the vertical center line (`pos.y + size.height / 2`). This missing coordinate constrained the pathfinder from routing cleanly around or exactly from the vertical center of nodes, leading to sub-optimal paths or edge overlaps for dynamically sized nodes.
**Action:** Always ensure routing grids are fully symmetric relative to the obstacle bounding boxes. Register both the horizontal and vertical centerlines (`xSet.add(pos.x + size.width / 2)` and `ySet.add(pos.y + size.height / 2)`) to provide the A* pathfinder with the most accurate internal geometry for shortest-path routing, improving layout capability and readability.
## 2024-05-18 - [Optimization] Horizontal Alignment Non-Overlap Property for Orthogonal Routing
**Learning:** In `@pgv/graph-core`, orthogonal edge routing logic within `routeEdgeOrthogonal` calculates vertical staggering heuristics for horizontal overlaps by comparing an edge's relative indices. Previously, it incorrectly failed to break the tie properly when `outIndex === inIndex`, only alternating based on `outIndex % 2` which resulted in overlaps.
**Action:** When evaluating staggered offsets for the horizontal alignment property in dense graphs, ensure the heuristic explicitly checks both `inIndex` and `outIndex`, utilizing the mod fallback `outIndex % 2` exclusively when they are perfectly equal (such as connecting identically sized layers). Additionally, always ignore the shared vertical downward line connecting to a single center port point during A* collision debugging tests (`y1 === source.y` or similar) as they inherently must overlap until staggering diverges.
